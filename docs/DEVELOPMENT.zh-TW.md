# 雙屏瀏覽器 開發筆記

> 套件名稱：正式版 `com.CYT.duobrowser`；測試版 `com.CYT.duobrowser.debug`（可以和正式版同時安裝）。
> 建置測試版：`powershell -ExecutionPolicy Bypass -File build.ps1`；正式版：加上 `-Release` → `dist\DuoBrowser-版本.apk`。
> 發行設定（itch.io 網址、客服信箱、檢查更新）在 `AppInfo.kt`。
> 正式版簽章金鑰放在 `release\`（不在版本控制裡），**一定要另外備份**，弄丟就無法再發布更新。
>
> 介面支援 English／繁體中文／简体中文（`Lang.kt`，每段文字用 `L.t(繁, 简, 英)` 寫在一起）。
> 品牌 logo：`res/drawable-nodpi/cyt_logo.png`，顯示在啟動畫面、第一次使用教學和「關於」頁。

這是一款 Android 瀏覽器，專為 Retroid Pocket Duo 這類有兩個螢幕的掌機設計。**一個網頁會從上螢幕一路延伸到下螢幕**，看起來像一張連在一起的長頁面。整個網頁只有一份 DOM、一個捲動位置，在任一個螢幕上滑動，兩個螢幕會一起捲動。

## 運作原理

```
              ┌──────────── 私有 VirtualDisplay（例：1920 × 2520）───────────┐
              │  WebView（唯一一個）                                          │
              │  ├─ 0 ~ 1080      ── 上螢幕負責的區域                          │
              │  ├─ 間距(可設定)  ── 藏在轉軸後面，不顯示                       │
              │  └─ 1080 ~ 2520   ── 下螢幕負責的區域（1280×960 依比例放大 1.5x）│
              └──────────────────────────────────────────────────────────────┘
                        │ ImageReader → 每格包成硬體 Bitmap（不經過 CPU 複製）
          ┌─────────────┴─────────────┐
   上螢幕 ScreenActivity       下螢幕 ScreenActivity
   畫出上半段                  畫出下半段 + 瀏覽器選單
          └── 觸控 / 手把游標座標換算回虛擬顯示器 → 注入 WebView ──┘
```

每個實體螢幕都有一個獨立的 `ScreenActivity`，各自屬於自己的 task。WebView、分頁和虛擬顯示器都放在 `Session` 裡，不屬於任何一個畫面。依照目前看得見哪些螢幕，會自動切換模式：

| 看得見的螢幕 | 模式 |
|---|---|
| 上屏 + 下屏 | 雙屏：網頁從上屏延伸到下屏 |
| 只剩下屏（例如上屏手勢回桌面） | 下屏變成一般的單屏瀏覽器 |
| 只剩上屏 | 上屏變成一般的單屏瀏覽器 |
| 都看不見 | 網頁暫停，分頁保留 |

切換模式時只會改變 WebView 的高度，不會重新載入網頁。從哪個螢幕的桌面點圖示，就在那個螢幕開啟；第一次啟動時會同時開啟另一個螢幕。之後在上屏再點圖示，就會恢復成雙屏。

- `Session.kt`：共用狀態、螢幕偵測與模式切換。
- `ScreenActivity.kt` / `MainActivity.kt`：分別是每個螢幕的畫面，以及桌面圖示的入口跳板。
- `SpanEngine.kt`：負責虛擬顯示器、畫格分配、觸控與游標注入，並把網頁彈出的下拉選單攔截下來，變成可以點的子 View。
- `Screens.kt`：每個實體螢幕上用來顯示網頁的 View。
- `Browser.kt`：WebView 設定、分頁、導覽，以及網頁輸入框和原生輸入面板之間的橋接。
- `BrowserUi.kt`：選單、網址列、分頁／書籤／歷史、設定、文字輸入面板。
- `GamepadController.kt`：實體按鍵的對應。
- `PdfViewer.kt`：PDF 下載與 pdf.js 閱讀器。

在只有一個螢幕的普通手機上，會把同一個螢幕切成上下兩塊來模擬，方便測試。

## 按鍵

以下是預設的按鍵對應（和畫面底部的按鍵提示一致）。除了兩支搖桿以外，都可以在「選單 → 設定 → 按鍵設定」裡自訂。

| 按鍵 | 預設功能 |
|---|---|
| 左搖桿 | 移動游標，可以從上螢幕一路移到下螢幕（固定） |
| 右搖桿 | 捲動游標底下的區塊（固定） |
| A | 點擊 / 確定；按住再推搖桿 = 拖曳 |
| B | 返回（選單開著時是關閉選單；已經沒有上一頁時只會提示，不會離開 App） |
| 十字鍵 ← / → | 上一頁 / 下一頁 |
| 十字鍵 ↑ / ↓ | 往上捲 / 往下捲 |
| L1 / R1 | 上一個分頁 / 下一個分頁（選單開著時切換頁籤） |
| L2 / R2 | 文字縮小 / 放大 |
| X | 網址列（再按一次關閉，回到網頁） |
| Y | 重新整理 |
| Start | 選單（分頁、書籤、歷史、設定） |
| Select | 下屏模式切換（放大裁切 ⇄ 完整顯示，不重新載入網頁） |
| L3 / R3 | 游標回到中央 / 回到頁首 |

選單開著時，十字鍵固定用來移動焦點；設成「點擊/確定」的按鍵用來確認，設成「返回」的按鍵用來關閉選單。

可以指定給按鍵的功能還有：新分頁、關閉分頁、往上/下翻一整頁、往左/右捲，以及電腦版/手機版切換。

觸控：兩個螢幕都可以直接點、滑、雙指縮放。下螢幕右下角的 ☰ 可以打開選單。

## 分頁

- 在選單裡可以看到所有分頁，點一下切換，按 ✕ 關閉。按「＋ 新分頁」會開一個顯示首頁的新分頁。
- 分頁和書籤可以用方塊或條列顯示（設定 → 一般）。長按可以拖動排序：拖到另一張卡片上時，左右（條列是上下）會出現亮線，放開就插在那裡（`enableReorderDrag`）。
- 標題、網站圖示變更時只更新卡片內容，不重建整頁（`tabUpdaters`），否則正在按的 ✕ 會被換掉。
- 卡片被手把選到時會浮起（translationZ），卡片上的 ✕、標記、亮線用更高的 elevation（`ABOVE_FOCUS`），否則觸控會被浮起的卡片搶走。
- 網頁用 `target=_blank` 或 `window.open` 打開的連結，會自動開在新分頁（無痕分頁開出來的也是無痕）。這種分頁在第一頁按返回，會關掉分頁、回到開它的那個網頁（`Tab.opener`）。
- 下次開啟 App 時，會還原上次開著的分頁，並停在上次正在看的那一個（網頁內換頁，例如 YouTube，也會記下）。

## 上屏工具列（設定 → 上屏工具列）

- 直式工具列放在上屏左邊，寬度 = 上下螢幕左緣的實際距離差（放大裁切時下屏左邊裁掉的寬度，依裁切比例自動計算）。網頁從工具列右邊開始排，所以網頁最左邊在下屏不會被裁掉。
- 按鈕：上一頁、下一頁、重新整理、首頁、網址、書籤（☆ 加入／★ 取消）、分頁（顯示數量，再按一次關閉）、下屏模式（圖示跟著模式變）、選單（再按一次關閉）。
- 手把：游標移到工具列上，底下的按鈕會變亮，按點擊鍵觸發。
- 實作：`SpanEngine.sideW` 讓 WebView 往右讓出寬度、下屏區域從網頁最左邊開始取；只剩下屏時沒有工具列。

## 歷史紀錄（`History.kt`）

- 造訪過的網址存在 App 資料夾的 `history.json`（不會上傳），同一網址只留最近一次，最多 1000 筆。PDF 閱讀器的網址也會記（App 內部的其他頁面不記），無痕分頁不記。
- 依日期分組顯示，點了開啟、✕ 刪除單筆、「清除全部」要按兩次。

## 書籤

- 選單和工具列的書籤鈕：目前網頁不在書籤裡就加入，已經在就取消。

## 電腦版網頁（預設開啟）

- 會改用電腦版的 User-Agent，並把網頁版面寬度強制設為 1280px（在設定裡可以調整成 768～1920）。每個網站分開記住。
- 可以在設定裡切換回手機版。

## 網頁裡的文字輸入

虛擬顯示器上的 WebView 拿不到系統輸入法，所以點到網頁的輸入框時，下螢幕會跳出原生輸入面板。你打的字會即時寫回網頁；按「送出 ⏎」等於在網頁上按 Enter。

網頁元件（shadow DOM）裡的輸入框也支援（例如 B 站留言框）：偵測時用 `composedPath()[0]` 取得真正被點到的元素，填字用 Range 選取後 `insertText`。

外觀是多行輸入框、其實是搜尋框的欄位（例如 Google 搜尋列：`role=combobox`、`enterkeyhint=search`、在搜尋表單裡），鍵盤的 Enter 會直接送出而不是換行。一般留言框等真正的多行輸入框仍然是換行。

App 畫面固定橫向，不會跟著裝置自動旋轉。

## PDF（內建閱讀器，`PdfViewer.kt`）

WebView 本身不能顯示 PDF，所以 App 自己處理：

- 點到網頁上的 PDF 連結（`application/pdf`，或網址／檔名是 `.pdf`）時，會帶著 cookie 下載到 `cache/pdf/`（無痕分頁放 `cache/pdf-inc/`，用無痕的 Cookie），在同一個分頁開啟閱讀器（按返回回到原本的網頁）。
- 選單的「PDF」可以從手機裡選一個 PDF；檔案管理員裡也可以用「雙屏瀏覽器」開啟 PDF。
- 閱讀器是 Mozilla 的 **pdf.js**（`assets/pdfjs/`，legacy 版，只留英文、繁中、簡中語系），由 `shouldInterceptRequest` 在 `https://appassets.androidplatform.net/` 底下提供：
  - `/pdfjs/...`：pdf.js 本身的檔案（不允許 `..`）。
  - `/duo-pdf/{id}/?name=檔名&src=原網址`：閱讀器頁面。照原檔提供 `viewer.html`，只在 `<head>` 前面加上 `<base>`、設定（語言、深色主題、觸控工具列、關閉 PDF 內的 JavaScript 和 eval）和隱藏用不到的按鈕（列印、下載、開檔、簡報模式、編輯註解）。
  - `/duo-pdf/{id}/檔名`：PDF 檔本身。
- 暫存只保留最近 15 份。暫存被清掉時，如果網址有 `src`（網頁上原本的 PDF 網址），閱讀器會自動重新下載。
- 讀到哪一頁由 pdf.js 自己記在 localStorage（無痕分頁的設定檔分開，關掉就清除）。

## 使用者腳本（油猴腳本，`UserScripts.kt`）

WebView 不能裝 Chrome 擴充功能，所以改支援 Tampermonkey 格式的 `.user.js` 腳本（例如沉浸式翻譯的油猴版）。

- 入口：設定 → 擴充功能 → 🧩 使用者腳本。有「沉浸式翻譯」一鍵安裝。電腦版網頁會把沉浸式翻譯的懸浮球放大 2 倍（網頁整體被縮小顯示，懸浮球原本太小）。
- 安裝：點到 `.user.js` 連結（例如 Greasy Fork 的「安裝」按鈕）、在網址列輸入腳本網址，或在腳本頁用「從網址／從檔案安裝」。會先顯示名稱、執行的網站與警告，按「安裝」才裝。`@require`、`@resource` 會一起下載。
- 管理：同一頁可以啟用／停用、更新（重新下載來源）、刪除（按兩下確認）。變更在重新整理網頁後生效。
- 腳本指令：腳本用 `GM_registerMenuCommand` 註冊的指令（例如沉浸式翻譯的「翻譯網頁」「開啟設定頁面」）會列在腳本頁最上面。
- 注入方式：每個啟用的腳本各自用 `addDocumentStartJavaScript` 註冊（一個腳本壞掉不影響其他），`@match/@include/@exclude`、`@run-at`、`@noframes` 在 JS 裡判斷。超過 512KB 的大型腳本只在主框架執行，由原生用 `evaluateJavascript` 載入，避免每個 iframe 都解析一次。
- 支援的 GM API：`GM_getValue/setValue/deleteValue/listValues`、`GM_addValueChangeListener`（同一頁內）、`GM_xmlhttpRequest`（不受同源限制，預設帶 cookie，`anonymous` 不帶）、`GM_addStyle/addElement`、`GM_registerMenuCommand`、`GM_openInTab`、`GM_setClipboard`、`GM_notification`、`GM_getResourceText/URL`、`GM_info`、`unsafeWindow`，以及 `GM.*` 的 Promise 版本。
- 安全：`DuoGM` 介面所有網頁都看得到，所以每次呼叫都要帶每次啟動隨機產生的 token，只有注入的腳本知道。無痕分頁不執行使用者腳本。
- 限制：iframe 裡的腳本收不到 `GM_xmlhttpRequest` 的回應和選單指令（回呼只送到主框架）；`GM_cookie`、`GM_download`（改成開新分頁）、`window.onurlchange` 沒有完整支援。

## 音量鍵

音量鍵只調媒體音量，範圍是完整的 0（靜音）～最大。已經最大聲還繼續按＋（或已靜音還按－）時，RP Duo 的雙屏助手會順便改動它自己的「下屏音量」；雙屏時 App 的聲音屬於上屏，不受影響。

## 設定

- **上下螢幕間距**：按「調整」後選單會收起，下屏底部出現調整列，按「▲ 下屏往上／▼ 下屏往下」（或十字鍵 ↑↓）即時移動下屏內容，邊看網頁邊調到跨過轉軸的內容接得起來。不重建畫面、不重新載入網頁（最多可調 400 虛擬像素）。
- **上下螢幕對調**：自動判斷錯誤時使用（預設把解析度較大的螢幕當作上螢幕）。
- 分頁／書籤顯示方式、電腦版/手機版、電腦版版面寬度、文字大小、游標速度、捲動速度、首頁、上屏工具列、使用者腳本、按鍵設定、主題、清除資料。
- 選單底部按鍵提示列的最右邊是「退出應用」：兩個螢幕一起關掉並結束程序（`Session.exitApp`）。

## 建置

需要 JDK 17 和 Android SDK（platform 35）。

```bash
./gradlew assembleDebug
```

`gradlew.bat` 在含中文的路徑下無法使用，所以 `build.ps1` 會直接呼叫 `%LOCALAPPDATA%\devtools` 裡的 Gradle。APK 會放在 `dist\DuoBrowser-debug.apk`，建置的中間檔則放在 `%LOCALAPPDATA%\DuoBrowserBuild`（刻意不放在 OneDrive 資料夾裡，可用環境變數 `DUO_BUILD_DIR` 改位置）。

## RP Duo 的下屏音量（重要）

RP Duo 系統裡的「雙屏助手」（`com.retroidpocket.dualscreen.assistant`）另外維護了一個**下屏音量**（`secondary_screen_volume_level`，範圍 0～15）。只要 App 在下屏有 Activity，它的聲音就會再乘上這個下屏音量。

這個下屏音量要在媒體音量已經是最大（或最小）之後，再繼續按音量鍵才會改變。結果就是：在下屏的 App 會出現「音量條已經滿了，聲音卻還能再變大」的現象。

所以這個 App 的處理方式是：

- **雙屏時**，下屏改用 Presentation 顯示，不放 Activity。這樣聲音會被當成上屏的聲音，音量鍵的行為就和其他 App 一樣。
- **只剩下屏時**（例如上屏回到桌面），下屏才改成 Activity。這時聲音確實是在下屏播放，所以會套用系統的下屏音量規則，和其他在下屏執行的 App 行為相同。

## 下屏顯示模式（設定 → 下屏顯示模式）

- **完整顯示**：把整個網頁寬度縮小放進下屏，所以下屏的內容比上屏小一些。
- **放大裁切**：下屏用和上屏相同的實際大小，取網頁正中間、和下屏一樣寬的一塊。內容和上屏完全對齊、不會錯位，左右超出的部分直接裁掉。這個模式下，游標在下屏時不會跑進被裁掉的區域。
- 只剩下屏的單屏模式一律使用完整顯示。
- 按 **Select** 鍵（或設定裡的「切換」）即時切換，影片不會中斷、網頁不會重新載入。看 YouTube 建議用完整顯示，下屏能完整看到留言與說明。

## 全螢幕影片（上屏看影片，下屏看網頁）

雙屏時，網頁要求全螢幕的影片只放在上屏，下屏繼續顯示網頁（假全螢幕，`INJECT_JS` 裡的 `__duoNativeFs`）。YouTube、Shorts、B 站有特別適配；其他網站也常常可以直接用。

## 按鍵設定（設定 → 按鍵設定（手把圖））

照 RP Duo 的按鍵位置畫出手把，每個按鍵上都標示目前的功能。點按鍵（或用十字鍵選到後按確定）就會列出可以指定的功能。同一頁還可以切換「左右搖桿功能交換」，也就是把游標和捲動對調。

## 固定頁面上推（雙屏時）

有些網頁剛好一頁高、不能捲動（例如 Google 登入頁），重要內容可能正好被轉軸切成兩半。這類頁面可以在上屏往上滑（或把游標放在上屏往下捲），最多可以把原本在下屏的內容完全推到上屏。往回滑會先把網頁推回原位。一般網頁捲動到頁尾時會停在原位。

如果網頁裡有還能捲動的區塊，會先讓那個區塊捲動。換頁或切換分頁時，上推的位置會自動歸零。

## Google 登入與人機驗證

Google 會封鎖從「內嵌 WebView」登入。所以這個 App 預設會把自己偽裝成一般的 Chrome：

- 移除含有 App 套件名稱的 `X-Requested-With` 標頭。
- User-Agent 拿掉 `wv` 標記。
- 瀏覽器回報的品牌（Client Hints）改成 Google Chrome。
- 補上一般 Chrome 才有的 `window.chrome` 物件。

但 Cloudflare 的人機驗證會發現「說自己是 Chrome、其實是 WebView」而一直驗證不過。所以：

- 偵測到 Cloudflare 驗證頁（`window._cf_chl_opt`）時，那個網站改用 WebView 原本的身分重新載入，並記住（`Prefs.siteCompat`，無痕分頁不記）。驗證通過的 Cookie 綁定 UA，所以之後這個網站都固定用原本的身分。
- Cloudflare Turnstile、hCaptcha、reCAPTCHA 的框架裡不執行 App 注入的任何腳本（`CAPTCHA_GUARD`），廣告阻擋也一律放行這些資源。

## 已知限制

- 網頁的 `<select>` 下拉選單如果以對話框形式出現，或是 JS 的 `alert`，會顯示在 App 所在的那個實體螢幕上，而不是網頁內。
- 位於 iframe 裡的輸入框目前不會觸發原生輸入面板。
